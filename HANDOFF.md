## 1. What this project is

A reliable webhook delivery platform (like Stripe's internal webhook system). Publishers send events; HookRelay fans them out to subscriber endpoints with retries, exponential backoff, dead-lettering, safe multi-worker concurrency, and HMAC signing. Built as a Docker + cloud-deployable resume project.

**Repo root:** `~/hookrelay`

## 2. Current status — everything below is DONE and verified working

- [x] Postgres running in Docker (`db` service)
- [x] Flask API (`api` service) — `POST /endpoints`, `POST /events`, `GET /endpoints`, `/health`
- [x] Event fan-out: one `Event` → many `Delivery` rows (one per subscribed endpoint)
- [x] Idempotency: duplicate `idempotency_key` → `200` replaying the **original** `event_id` + `duplicate: true` (was `409`, which dead-ended a publisher that lost its response)
- [x] Worker (`worker` service): polls, claims via `FOR UPDATE SKIP LOCKED`, delivers via real HTTP POST
- [x] Safe concurrency: verified with 2 workers running simultaneously, zero duplicate deliveries
- [x] Crash recovery: lease (`locked_until`/`locked_by`) + `sweep_expired_leases()`
- [x] `attempt_count` counted at **claim** time, so a worker that crashes mid-request is bounded too — verified live (a job at 5 crashed attempts now sweeps to `dead` instead of looping forever)
- [x] Lease sweeper uses `FOR UPDATE SKIP LOCKED` + a 50-row batch, so concurrent sweepers don't collide and a renewed lease isn't stolen
- [x] Exponential backoff (10s→30s→60s→120s→300s w/ **one-directional** jitter) + dead-letter after 5 attempts — verified live. Jitter no longer fires *earlier* than the base delay.
- [x] HMAC-SHA256 signing of every outbound delivery (`X-HookRelay-Signature`, `X-HookRelay-Timestamp` headers) — verified via webhook.site headers
- [x] **Deliveries carry `event_id` + `delivery_id` inside the signed body** (mirrored as `X-HookRelay-Event-Id` / `X-HookRelay-Delivery-Id`) so a subscriber can dedupe a redelivery after a crash. They're in the body because the signature only covers `"{timestamp}.{body}"` — a bare header would be unsigned.
- [x] **Automated test suite** — 56 pytest tests in `tests/`, run against a separate `hookrelay_test` database. Covers backoff bounds, `SKIP LOCKED` (real row locks, not mocks), crash recovery, idempotent replay, signing, the replay guards, the lease heartbeat, and endpoint management. `./venv/bin/python -m pytest`
- [x] Alembic migrations wired up — both `api` and `worker` containers run `alembic upgrade head` on startup before doing anything else (fixes race condition where worker started before tables existed)
- [x] **Entire stack runs with one command: `docker compose up -d`** — db + api + worker, fully containerized, verified end-to-end (registered endpoint → sent event → worker delivered with valid signature, all inside Docker)
- [x] **Failure visibility dashboard** — `GET /dashboard` (server-rendered, no new deps) over `GET /deliveries?status=`, `/deliveries/stats`, and `POST /deliveries/<id>/replay` (US-3.1, US-3.2)
- [x] **Browsable front page** — `GET /` shows stats, registered endpoints, an API reference, and a working "send a test event" form; `GET /events` renders that same page instead of a bare 405 (POST-only routes stay POST-only for machines)
- [x] **Dead-letter + replay verified end-to-end** — forced a delivery through all 5 attempts to `dead`, fixed the endpoint, replayed it via the API, watched the worker deliver it with a valid signature
- [x] **Double-delivery bug found and fixed** — registering the same URL twice created two endpoint rows, so every event was delivered to that subscriber twice. Fixed with `UniqueConstraint("url", "event_type")` on `endpoints` (migration `bc5a376aa80e`, which also collapses the existing duplicate rows and repoints their deliveries) plus a `409` in `POST /endpoints`
- [x] **Endpoint management** — `PATCH /endpoints/<id>` (rotate secret / correct URL, shared `validate_endpoint_patch()`, `409` on collision) and `DELETE /endpoints/<id>` (refuses `409` while any delivery is `in_flight`, otherwise removes child delivery history in the same transaction and reports the count)
- [x] **All timestamps are `TIMESTAMPTZ`** — `created_at`, `next_attempt_at`, `locked_until` are `DateTime(timezone=True)`, so the API returns an explicit `+00:00` offset. Migration `c238d8f0b655` uses an explicit `postgresql_using="<col> AT TIME ZONE 'UTC'"` on every `alter_column`; **Alembic's autogenerated output omits `USING`**, which would reinterpret historical rows in the session timezone and silently shift them
- [x] **Lease heartbeat** — `_LeaseHeartbeat` renews `locked_until` every 10s while a delivery is in flight, so a request outliving the 30s lease isn't duplicated by the sweeper. Guarded on `id` + `locked_by` + `status`, so a worker whose lease was stolen **stops renewing** instead of keeping a foreign lease alive forever

## 4. Data model (shared/models.py)

```python
class Endpoint(Base):
    __tablename__ = "endpoints"
    id = Column(UUID, primary_key=True, default=uuid.uuid4)
    url = Column(String, nullable=False)
    secret = Column(String, nullable=False)
    event_type = Column(String, nullable=False)
    created_at = Column(DateTime, default=...)
    # stops the same URL being registered twice for one event type,
    # which used to make every event double-deliver (US-3.x hardening)
    __table_args__ = (UniqueConstraint("url", "event_type", name="uq_endpoint_url_event_type"),)

class Event(Base):
    __tablename__ = "events"
    id = Column(UUID, primary_key=True, default=uuid.uuid4)
    event_type = Column(String, nullable=False)
    payload = Column(JSONB, nullable=False)
    idempotency_key = Column(String, nullable=False, unique=True)
    created_at = Column(DateTime, default=...)
    deliveries = relationship("Delivery", back_populates="event")

class Delivery(Base):
    __tablename__ = "deliveries"
    id = Column(UUID, primary_key=True, default=uuid.uuid4)
    event_id = Column(UUID, ForeignKey("events.id"), nullable=False)
    endpoint_id = Column(UUID, ForeignKey("endpoints.id"), nullable=False)
    status = Column(String, default="pending")  # pending/in_flight/succeeded/retrying/dead
    attempt_count = Column(Integer, default=0)
    next_attempt_at = Column(DateTime, default=...)
    locked_until = Column(DateTime, nullable=True)
    locked_by = Column(String, nullable=True)
    last_status_code = Column(Integer, nullable=True)
    last_error = Column(String, nullable=True)
    created_at = Column(DateTime, default=...)
    __table_args__ = (UniqueConstraint("event_id", "endpoint_id"),)
```

Status flow: `pending → in_flight → succeeded` OR `→ retrying → in_flight → ... → dead`

## 5. How to resume work (commands)

```bash
cd ~/hookrelay
docker compose up -d          # starts db, api, worker (migrations run automatically)
docker compose ps             # confirm all 3 are Up/healthy
docker compose logs -f        # watch all logs live

# Test it's alive:
curl http://127.0.0.1:5000/health

# Register an endpoint + send an event:
curl -X POST http://127.0.0.1:5000/endpoints \
  -H "Content-Type: application/json" \
  -d '{"url": "https://webhook.site/YOUR-ID", "secret": "mysecret", "event_type": "order.created"}'

curl -X POST http://127.0.0.1:5000/events \
  -H "Content-Type: application/json" \
  -d '{"event_type": "order.created", "payload": {"order_id": 1}, "idempotency_key": "unique-key"}'

docker compose logs worker --tail 20   # or: docker compose logs worker | grep -i "OK\|FAIL\|DEAD"
```

**To wipe and start fresh (loses all data):**
```bash
docker compose down -v
docker compose up -d
```
(No manual schema step needed — Alembic runs automatically on container start.)

docker compose build api worker   # rebuild images with new code

## 7. Key interview talking points (already earned, don't need to build more to say these)

- At-least-once delivery, not exactly-once — explain why, and how idempotency keys + the `event_id` now carried in the signed body let subscribers dedupe
- `SELECT ... FOR UPDATE SKIP LOCKED` for safe concurrent job claiming — no separate queue system needed
- **Counting attempts at claim, not at failure** — the failure-path counter was invisible to a crashed worker, so a job that killed the worker retried forever
- **One-directional retry jitter** — symmetric jitter can fire a retry *earlier* than the base delay, re-synchronising the cohort the backoff was spreading out
- **Replaying the original result on a duplicate idempotency key** instead of `409`, because a publisher that lost a response can't recover from a conflict
- Lease-based crash recovery (`locked_until`) instead of a dead-worker detector service
- Exponential backoff with jitter, bounded retries, dead-letter queue
- HMAC-SHA256 signing with timestamp to prevent replay attacks — and why the IDs live in the *body* the signature covers, not in headers
- **Testing Postgres rather than mocking it** — the concurrency guarantees live in the database, so the tests take real row locks
- Chose Postgres over Kafka/Redis deliberately — the problem is per-endpoint delivery tracking, not raw throughput; mention how you'd add Redis later as a speed layer if scale demanded it, without changing the source of truth
- Alembic migrations run automatically in both containers on startup, avoiding manual schema management
